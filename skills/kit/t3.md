# T3 Code: how to drive it

T3 Code runs agent threads in a desktop app. A session inside T3 has its tools as MCP tools named `mcp__t3-code__*`. They are often deferred: load a tool with ToolSearch before you call it. These facts were checked in November 2026. When a tool's own description disagrees with this file, trust the description, then fix this file.

## Your address

`$T3CODE_THREAD_ID` is this thread's id. Put it in briefs and specs so other threads can reach you.

## A visible session for Sid (spinoff)

- Open one with `t3_thread_launch`, passing `title` ("Discuss: <part>") and `message` (the first prompt).
- Leave out the model and modes, so the thread inherits this thread's provider, model and account.
- It opens at the project root by default. If this thread runs in a worktree, pass `workspaceStrategy: {type: "existing_worktree", worktreePath: <this folder>}`, so both threads edit the same files.
- Give Sid the `link` from the result. Mention a thread to Sid only by its link.

## Messages between threads

- `t3_thread_send` with `threadId` and `message`. Use mode `queue` for reports such as "saved", so they wait for the recipient's turn. Use `auto` only when the message should steer a turn that's running now.
- `t3_thread_list` lists the threads, which is how a resumed main finds its open sessions.
- `t3_thread_read` shows what another thread has done. Read a thread before you answer a question about it.

## Children that do work (build, expert)

- Start a child with `delegate_task`, passing `task` (the full brief: the child has no other context), `title` and `role`.
  - `isolation: "shared"` works in this checkout.
  - `isolation: "worktree"` gives the child its own checkout, started from the last commit.
- Results arrive as notifications. Follow the `next` hint, and don't poll.
- Stop a child you no longer need with `task_cancel`.
- For other model families, call `orchestrator_capabilities` first to see which providers and models are available. Then pass `target` with the provider and model. OpenCode through OpenRouter reaches several families. If a model is unavailable, say so instead of substituting.
- `t3_background_wait` takes only Bash or Monitor task ids, not subagent or delegate ids.
